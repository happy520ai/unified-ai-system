# ADR-012 验收中写死的历史治理计数以最新实测穷尽读数为准，且不改验收文字

- 日期: 2026-09-22
- 状态: 已接受

## 背景

多条 M2 任务的 acceptance 逐字写死了登记当时的治理计数（48 errors / 46 unresolved / 47 unresolved / 111 private-interface / 159 总告警）。这些数字在后续实测中被逐一推翻：最新 audit_governance 读数为 113 error + 6 warning（census total 119）、private-interface 110、unresolved-dependency 0（成因已归因为 ./X.js specifier 被非 TS 感知解析器误判）。约束是「被考核方不得解释标准」：我既不能改 acceptance 文字去凑实测，也不能制造条目凑回旧数字，不裁就只能让这批任务永久 in_progress。2026-09-22 owner 就 B-13 与 B-23 给出同一口径的答复：「以最新实测穷尽读数为准」。

## 决定

判定这类 acceptance 时，以最新一次 list_governance_issues 穷尽分页读数 + audit_governance 摘要行为准，且两个独立来源同值才算复现；acceptance 原文一字不动，作为历史背景保留。收口时 result_note 必须并列「验收原文的历史计数」与「本轮实测穷尽读数」并写明差异成因，不得抹掉前者。unresolved 的计数口径取 SUPERSEDED_BY_CENSUS：以普查（实测 0 条）为验收对象，按「经验证的缺席」如实收口。理由：验收文字是登记时刻的快照，而治理读数是可复测的现值；把快照当成永久判据会迫使执行方在「改标准」与「造数据」之间二选一，两者都破坏证据链。

## 后果

正面：T-075 / T-078 / T-082 / T-084 的验收对账前置解除；实测适用臂 b1_plus_b13_plus_b23 = T-076 / T-078 / T-082 三条（仍须 DONE_GATE 绿矩阵才真正翻牌，裁定本身不翻牌）。代价与边界：① 这不等于「数字可以随便改」——读数必须来自穷尽分页 + 交叉源同值，单一过滤读数不算（list_governance_issues 不校验 code 词表，拼错的 code 同样返回 total 0，故过滤后的 0 无法区分「已清零」与「查无此项」）；② 边界守护不随本裁定变化：private-interface 110、file-cycle 6、undeclared-dependency 2，任一随收口一起变动即说明判据被改宽而非问题被解决；③ 被放弃的方案是「按验收原文数字执行」——那需要反向改审计或制造条目凑数，两者都在禁令内，其诚实终态是永久 in_progress；④ 本裁定只覆盖「acceptance 点名历史计数」这一类，不构成对任何 acceptance 文字的通用改写权。落地记录：.pm/rulings-20260922.md（含本轮四条裁定原文、实测限定与重启后执行顺序）。
