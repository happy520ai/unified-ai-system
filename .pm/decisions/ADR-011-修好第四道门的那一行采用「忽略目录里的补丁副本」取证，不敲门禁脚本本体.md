# ADR-011 修好第四道门的那一行采用「忽略目录里的补丁副本」取证，不敲门禁脚本本体

- 日期: 2026-09-20
- 状态: 已接受

## 背景

第四道门 `pnpm verify:public-clone` 在 Windows 上自 2026-09-20 起停在无凭据安装阶段。2026-09-21 实测定因：`tools/verify-public-clone.mjs:153-183` 将 `USERPROFILE`/`LOCALAPPDATA` 重定向入一次性 home，而 `:224-227` 只建 `appdata`/`localappdata`，从不建 Windows 实际使用的 `<home>\AppData\Local`；MSBuild 的 C++ `FileTracker.FileIsUnderNormalizedPath` 在此组合下抛 `IndexOutOfRangeException`，令 `better-sqlite3` 源码重建崩。约束：项目规矩要求改动可逆、不擅改共享门禁判定。

## 决定

取证手段选「在 `.pm/`（被 `.gitignore:100` 忽略）里放一份打了那一行的副本 `verify-public-clone.patched.mjs` 跑端到端」，而**不擅自修改 `tools/verify-public-clone.mjs` 本身**，也不为了跑通而提交。具体取舍：（一）该验证器以「tracked 工作树干净」为前置，所改它**无法自对自己补丁**（一改就脏、停在第一项检查），所改自验证路径不存在；（二）副本里 `repoRoot = resolve(dirname(file), "..")` 仍解析到仓库根，克隆源是**未改动的 HEAD**，因此产品侧零改动而安装侧真实；（三）结论只挂在可复现命令上（台账 §24），而不挂在「谁改的」上。
