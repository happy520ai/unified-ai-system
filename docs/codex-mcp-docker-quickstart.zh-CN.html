用 Docker 将 Codex 接入 MCP Server

注册一个固定版本的容器，检查 9 个工具，并在无需克隆仓库、无需配置 Provider API Key 的情况下完成首次安全调用。

约 1 分钟 9 个 MCP 工具 默认 Fake Provider
最短路径

执行一条 codex mcp add 命令，重启 Codex，再运行 /mcp verbose。MCP 会话启动时自动拉起隔离网关，会话结束后自动清理。

目录 准备工作 1. 注册 MCP Server 2. 验证 9 个工具 3. 完成安全调用 测试证明了什么 诊断与卸载

只需要 Codex CLI 和正在运行的 Docker Engine。首次验证不需要其他依赖。

公开容器同时支持 linux/amd64 与 linux/arm64。 默认路径不会读取 Provider Key；除非另行提供明确、受限的真实 Provider 授权， Chat 始终使用确定性的本地 Fake Provider。

步骤 01 / 注册

添加固定版本的 MCP Server。

在终端执行下面的命令。-- 后面的内容，就是 Codex 建立 MCP 连接时启动的 stdio Server 命令。

$ codex mcp add unified-ai-system -- docker run --rm -i ghcr.io/happy520ai/unified-ai-system/mcp-server:0.4.6

在启动新会话前，先确认 Codex 保存了预期的镜像和参数：

$ codex mcp get unified-ai-system --json

步骤 02 / 检查

重启 Codex，确认 9 个工具。

注册完成后打开一个新的 Codex 会话，在终端界面运行 /mcp verbose。连接应显示以下 9 个工具：

Gatewaygateway_health、gateway_readiness、gateway_prompt_enhance、gateway_chat
Knowledgeknowledge_readiness
Workflowsworkflow_health、workflow_actions
Workforceworkforce_health、workforce_agents

已经打开的 Codex 会话不会热加载刚注册的 MCP 定义，因此重启会话是安装步骤的一部分。

步骤 03 / 验证链路

先增强需求，再验证 Chat 执行证据。

把下面的内容作为普通 Codex Prompt 发送。它会先证明提示增强没有调用 Provider，再检查安全边界并调用 Gateway Chat。

> 先使用 gateway_prompt_enhance 把“帮团队做一个小型 API”整理成编程提示词，并证明没有调用 Provider；然后检查网关健康状态和就绪状态，只有网关明确证明处于纯 Fake 模式时，才通过 Gateway Chat 发送 MCP_READY。报告 Provider、Model、执行模式和响应。

证据边界

准确理解这次测试证明了什么。

成功运行可以证明：Codex 已加载 stdio Server，受管网关通过健康边界， 已发布的 Fake Provider 路径返回了响应；同时可以使用无需 Provider 的提示 增强，并读取 Knowledge、Workflow 和 Workforce 的只读检查面。

已经证明公开镜像、MCP 连接、9 个工具、本地提示增强、Fake Provider 请求
没有授权付费 Provider、Workflow 执行、Agent 派发、数据修改
没有宣称生产就绪、L5 自主或 AGI

诊断 / 卸载

让安装过程始终可检查、可撤销。

如果看不到 Server，先确认 Docker，再检查保存的 MCP 定义，并在重新启动 Codex 后使用 /mcp verbose。

$ docker info

不再使用时可以直接移除。下一个 Codex 会话将不再启动该 Server。

$ codex mcp remove unified-ai-system

更多安全任务见源码快速上手； 已发布包的元数据可在官方 MCP Registry 条目中独立核验。
