# Quality Trend Digest Guide

This guide defines how to use the operational digest generated by
`pnpm quality:trend-digest` when CI is healthy but quality is still unstable.

## Why this digest exists

- `quality:trend-summary` gives a full table and guardrail verdict.
- `quality:trend-digest` gives a fast executive signal plus latest-run risk signals.
- `quality:trend-digest.json` is machine-readable and suitable for dashboards.

## Run locally

```bash
pnpm quality:trend-digest -- \
  --trend .tmp/quality-trend.json \
  --output .tmp/quality-trend-digest.md \
  --json-output .tmp/quality-trend-digest.json \
  --short-window 7 \
  --long-window 30 \
  --max-consecutive-failures 3 \
  --max-score-drop-points 20
```

## What changed in the digest output

The digest now includes:

- `state`: quick stability state (`stable` / `unstable`) for operational triage.
- `sample.latestRun`: latest run score, required score checks, verification outcome and drill status.
- `passRatePercent`: pass ratio for both short and long windows.
- `verificationIssueCount`: count of verification issues accumulated in each window.
- `drillRecommendation`: recommendation from recovery drill dry-run payload.

## Interpretation

- `state = stable`
  - Recent windows are meeting stability thresholds with no obvious one-window risk flags.
- `state = unstable`
  - Investigate latest verification issues and drill status immediately.
  - Review `.tmp/quality-trend-summary.md` for context.
  - Run:
    - `pnpm quality:trend-summary -- --trend .tmp/quality-trend.json --output .tmp/quality-trend-summary.md --guard-output .tmp/quality-trend-guardrail.json --enforce-guardrails`
    - `pnpm quality:ci -- --json --require-score 165`

## CI artifacts

Current CI pipelines publish:

- `.tmp/quality-trend-digest.md`
- `.tmp/quality-trend-digest.json`
- existing trend and quality artifacts (`.tmp/quality-trend.json`, `.tmp/quality-scorecard.json`, `.tmp/quality-ci-verification.json`)

## Escalation flow

1. Confirm whether this is a score drift or verification issue in the latest run.
2. If verification issues exist, trace the first gate failure in `quality-ci-verification.json`.
3. If drift is abrupt, compare the last two scorecards and inspect changed checks.
4. Re-run CI locally after applying fixes before the next merge or release.
