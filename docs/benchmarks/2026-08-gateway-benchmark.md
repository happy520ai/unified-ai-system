# Gateway Infrastructure Benchmark — 2026-08

Reproducible micro-benchmark of the gateway's **own hot-path overhead**, run
with the deterministic fake provider so no provider latency pollutes the
numbers. Generated by `tools/gateway-benchmark.mjs`.

```bash
node tools/gateway-benchmark.mjs --json benchmark.json
```

## Environment

- Node `v25.8.1`, `win32-x64`, single node, loopback HTTP
- Provider: `local-fake-model` (deterministic, zero credentials)
- Auth: enterprise mode with an admin token (and, where noted, a `uai-` virtual key)
- 3 warmup requests per suite; sequential unless stated otherwise

## What this does and does not measure

These numbers measure **gateway infrastructure overhead only**: routing,
auth, budget gates, caching, guardrail scanning, and serialization. They say
nothing about model quality, real-provider latency, or multi-node scaling.
Cloud gateways typically add 10–50 ms of proxy latency; publishing our own
overhead makes the comparison honest instead of hand-wavy.

## Results

| Suite | n | mean | p50 | p95 | p99 |
| --- | --- | --- | --- | --- | --- |
| Chat JSON (non-streaming) | 150 | 15.83 ms | 15.57 ms | 16.45 ms | 28.55 ms |
| Chat SSE — time to first token | 80 | 2.97 ms | 2.81 ms | 3.70 ms | 10.43 ms |
| Chat SSE — total stream | 80 | 156.09 ms | 155.79 ms | 157.68 ms | 172.89 ms |
| Prompt enhance (`/prompts/enhance`) | 60 | 2.17 ms | 2.11 ms | 2.81 ms | 3.62 ms |

Throughput (JSON chat, concurrency 8): **402.15 req/s** over 247 requests in
614 ms wall time.

### Response cache — hit vs miss

`AI_GATEWAY_RESPONSE_CACHE_ENABLED=true`, same request body repeated (exact
hits after the first populate):

| Phase | n | mean | p50 | p95 |
| --- | --- | --- | --- | --- |
| Cache disabled | 120 | 15.96 ms | 15.57 ms | 16.47 ms |
| Cache enabled (hit path) | 120 | 3.22 ms | **2.79 ms** | 4.17 ms |

Cache hits cut median latency by **~82%** (15.57 → 2.79 ms) and skip the
provider call entirely — the hit path is pure lookup plus byte-identical
replay.

### Guardrail scan overhead

`AI_GATEWAY_GUARDRAILS_ENABLED=true` with the default deterministic rule set,
benign input (no findings fired):

| Phase | n | mean | p50 | p95 |
| --- | --- | --- | --- | --- |
| Guardrails disabled | 120 | 15.86 ms | 15.58 ms | 16.22 ms |
| Guardrails enabled | 120 | 16.03 ms | 15.64 ms | 16.31 ms |

Enabling guardrails costs **< 0.2 ms mean** on this workload — under ~1% of
request latency. Blocking rules (pasted secrets, banned terms) short-circuit
before the provider call and therefore *save* the provider cost when tripped.

### Virtual-key budget gate

Requests authenticated with a `uai-` virtual key carrying a daily token
budget and rate limit, vs the admin-token baseline: p50 15.54 ms vs
15.57 ms — the budget/rate pre-check is effectively free on the hot path.

## Reproducing

```bash
git clone https://github.com/happy520ai/unified-ai-system.git
cd unified-ai-system
pnpm install --frozen-lockfile
node tools/gateway-benchmark.mjs
```

The tool boots and tears down its own gateway instances (one per phase) on a
loopback port (default `3197`), so no other gateway should hold that port.
Raw JSON for this report: same run, `--json` output.
