Unified AI System

面向模型、智能体、知识与工具的自托管 AI 能力网关。 通过一个可治理的 MCP 边界连接 Codex、Cursor 或 Cline。

接入你的智能体 查看 v0.3.3
$ docker run --rm ghcr.io/happy520ai/unified-ai-system/ai-gateway-service:0.3.3 pnpm gateway demo

首次验证只使用 Fake Provider。真实 Provider 执行必须显式启用并限定范围。

8可治理的 MCP 工具
2CPU 架构镜像
Apache-2.0开源许可

一个运行时 / 三种客户端

在智能体工作的地方接入网关。

以下方式都会启动同一个已发布、无需凭据的 MCP 容器，不需要克隆仓库。

直接连接 MCP

Codex

注册已发布的 stdio Server，重启 Codex，然后通过 /mcp 检查连接。

codex mcp add unified-ai-system -- docker run --rm -i ghcr.io/happy520ai/unified-ai-system/mcp-server:0.3.3

生成本地配置

Cursor

生成本地 Cursor MCP 配置，不写入任何 Provider 凭据。

pnpm dlx add-mcp@2.0.0 "docker run --rm -i ghcr.io/happy520ai/unified-ai-system/mcp-server:0.3.3" --name unified-ai-system -a cursor -y

直接安装 MCP

Cline

通过 Cline CLI 安装同一个 Server，并使用隔离的 stdio 传输。

cline mcp install unified-ai-system --yes --json -- docker run --rm -i ghcr.io/happy520ai/unified-ai-system/mcp-server:0.3.3

网关边界

默认即可验证，关键执行必须明确。

01

检查

通过只读 MCP 工具查看健康、就绪、工作流、知识和 Workforce 状态。

02

路由

一个网关边界将智能体客户端与 Provider 选择、模型路由和执行策略分离。

03

控制

本地 Fake Provider 是无凭据默认值；真实调用需要显式、限定范围的授权。
